# The suite population contract (POP-01, POP-02), checked by tests/check_population.cmake as the
# `population` entry. For every active gate, the suites listed here must equal the suites the
# built binary holds (`zen-tests --list-test-suites`), so adding or renaming a suite is a line
# here; and each suite must select at least `min-cases` cases (`--count`: cases, never
# assertions). A floor is the measured count with no slack: deleting a case crosses it, adding
# one is free. The OS-enforcement tallies are exact instead (tests/enforcement_gate.hpp).

# `gate` says why a suite may be absent: `portable` never; `kernel` rides `TARGET zen-kernel`
# (Linux, and Windows under LOOM_ENABLE_WINDOWS_KERNEL); `posix` rides `NOT WIN32`; `runs` rides
# `TARGET zen-runs` (the kernel and LOOM_BUILD_SESSION_TOOLS). An absent gate's suites are
# declared absent, never passed. A suite's floor is the sum of its rows whose gate is active, so
# a suite smaller on Windows says so with a second row: `bridge` (the unix-socket cases) and
# `kernel` (the RTLD_NOLOAD unload observations) each have cases behind `#ifndef _WIN32`.
